# Plan — shadcn skin as a subpath (`adt-html-editor/shadcn`)

A second, optional UI for the editor built with shadcn/ui components, published from the **same package** under the `adt-html-editor/shadcn` subpath. The main entry (`adt-html-editor`) keeps zero UI dependencies; the shadcn entry brings its own peer dependencies, and a consumer that never imports the subpath never loads them.

Priorities, in this order: **1) the core entry stays dependency-free and its bundle does not grow, 2) behaviour parity with the core parts (DnD, keyboard, a11y, history), 3) idiomatic shadcn.**

Patterns applied: `vercel-composition-patterns` (compound parts, `state / actions / meta` contexts, explicit variants, headless hooks + styled parts), `vercel-react-best-practices` (no re-render per drag frame, `bundle-*` rules), the `shadcn` skill (composition and styling rules, CLI-first) and `react-doctor` as the acceptance criterion.

---

## 0. Goal and non-goals

| | Core entry `adt-html-editor` | Skin entry `adt-html-editor/shadcn` |
|---|---|---|
| Dependencies | Unchanged: pdnd, `@tanstack/store`, `tailwindcss` (worker), `tailwind-merge`, `tiny-invariant` | Adds **optional peers**: `@base-ui/react` (or `@radix-ui/*`), `lucide-react`, `class-variance-authority`, `clsx` |
| Styling | CSS Modules + `--adt-*` tokens, shipped in `dist/style.css` | Tailwind utility classes compiled by the **consumer's** Tailwind, shadcn theme tokens (`bg-background`, `text-muted-foreground`) |
| Logic | Owns all state, DnD, keyboard, history, geometry | Owns **nothing**: every part is a thin view over a core hook or context |
| Public API | `HtmlEditor.*` namespace and standalone parts | `HtmlEditor.*` namespace with the **same part names**, plus a `DefaultLayout` |

Non-goals: a theme switcher inside the library, changing how the canvas is styled (the canvas is document content, not editor chrome), publishing to npm.

## 1. Architecture decisions

| Topic | Decision | Why |
|---|---|---|
| Packaging | Second Rollup entry in `vite.lib.config.ts`: `{ index: 'src/lib/index.ts', shadcn: 'src/shadcn/index.ts' }`, `exports["./shadcn"]` in `package.json` | One repo, one version, shared chunks for the core code; the subpath is what makes the split visible to bundlers. |
| Tree-shaking guarantee | The core entry **never imports** `src/shadcn/**`; the skin imports the core through relative paths (`../lib/...`), so Rollup puts shared code in chunks that `dist/index.js` also uses, and shadcn peers appear **only** in `dist/shadcn.js` and its chunks | `bundle-conditional`: the consumer pays for shadcn only when importing `/shadcn`. Enforced by lint and by a build test (§3.6), not by convention. |
| Dependency declaration | Skin peers in `peerDependencies` + `peerDependenciesMeta: { optional: true }`; also in `devDependencies` for the playground and tests | Installing the package does not pull shadcn deps; importing `/shadcn` without them fails loudly at bundle time with a clear module-not-found error. |
| Primitive base | CLI default for shadcn v4 (`base`, i.e. `@base-ui/react`). Decision point before S1: if the consuming app already uses `radix`, pick `radix` to avoid two primitive libraries in that app | Whichever base is picked, the skin code uses `render`/`asChild` per `rules/base-vs-radix.md`; the choice is a `components.json` setting, not spread through the code. |
| Where shadcn UI lives | `src/shadcn/ui/*` generated by the CLI (`components.json` at the repo root with `aliases.ui → src/shadcn/ui`, `aliases.utils → src/shadcn/lib/utils`), never hand-written | The CLI's `add --diff` keeps them updatable; components are code we own, as shadcn intends. |
| Import alias | `@shadcn/*` → `src/shadcn/*` in `tsconfig.app.json` `paths` and in the Vite `resolve.alias` for both lib and playground configs; `src/lib` keeps relative imports only | The CLI needs an alias; the core must stay alias-free so `tsconfig.types.json` output is portable. |
| Skin CSS | **No precompiled CSS** for the skin. The consumer's Tailwind v4 compiles the classes through `@source "../node_modules/adt-html-editor/dist"` and provides the shadcn theme tokens in its own global CSS | shadcn's model: the consumer owns the theme. Precompiling would freeze one theme and duplicate the preflight. |
| Core CSS with the skin | The skin still requires `adt-html-editor/style.css` for canvas-related overlays (`SelectionOverlay`, ghosts, guides, handles) that are not chrome | Those visuals sit inside the page and must not depend on the consumer's Tailwind. Documented in the README. |
| Headless first | Every core part gets a hook (`useX`) that returns `{ state, actions, meta }` or props objects with all `data-*`/aria attributes and event handlers. Core styled parts and shadcn parts are two consumers of the same hook | `state-decouple-implementation`, `patterns-children-over-render-props`. The skin cannot drift in behaviour because it does not reimplement any. |
| Namespace | `src/shadcn/index.ts` exports `HtmlEditor` (same shape: `Layers`, `Canvas`, `Inspector`, `Palette`, `History`, `Layout`, `DefaultLayout`) built from skin parts; `Canvas` children that are not chrome (`FixedPage`, `Guides`, `LiveGhost`, `ImageGhost`, `Handles`, `Viewport`) are **re-exported** from the core | A consumer swaps `import { HtmlEditor } from 'adt-html-editor'` for `'adt-html-editor/shadcn'` and nothing else changes. |
| Composition | No boolean props to switch skins; explicit imports from two entries are the variant mechanism | `architecture-avoid-boolean-props`, `patterns-explicit-variants`. |
| React 19 | Skin components use `use()` for contexts and pass `ref` as a prop; no `forwardRef` (the CLI output for v4 already follows this) | `react19-no-forwardref`. |

## 2. Folder structure

```
components.json                       # aliases.ui = src/shadcn/ui, aliases.utils = src/shadcn/lib/utils, base, style, iconLibrary
src/
  lib/                                # core, unchanged surface, gains headless hooks (§3.1)
  shadcn/
    index.ts                          # public surface of adt-html-editor/shadcn
    lib/utils.ts                      # cn() (CLI-generated)
    ui/                               # CLI-generated shadcn components (button, input, tabs, ...)
    parts/
      Editor/{HtmlEditor,DefaultLayout,HistoryParts}.tsx
      Layers/{LayersPanel,LayersParts,LayerRow}.tsx
      Canvas/{CanvasToolbar,WidthPresets,DarkToggle,Zoom}.tsx
      Inspector/{InspectorPanel,InspectorParts,ClassChips,ClassCombobox,AttributeFields,controls/*}.tsx
      Inspector/{Position,Transform}.tsx
      Palette/Palette.tsx
    __tests__/
      conformance.test.tsx            # shared part contract run against core and skin (§3.5)
      bundle.test.ts                  # dist graph assertion (§3.6)
  playground/
    index.css                         # adds @import "tailwindcss" + shadcn tokens, @source limited to src/shadcn
    ShadcnLayout.tsx                  # playground layout option "shadcn"
```

`src/lib/**` must not import from `src/shadcn/**` or from any skin peer. `src/shadcn/**` imports the core only through `../lib/...` (or `../../lib/...`), never through the package name.

## 3. Detailed design

### 3.1 Headless extraction in the core (prerequisite)

Hooks to add or complete, each returning stable objects with the attributes the styled part spreads today. Existing: `useLayerRow`, `useClassEditing`, `usePaletteDraggable`, `useHistory`, `useLayersContext`, `useInspectorContext`, `useCanvasContext`, `useCanvasInteractions`, `useKeyboardMove`.

| Part today | Hook to extract | Returns |
|---|---|---|
| `LayersSearch` | `useLayersSearch()` | `{ inputProps, query, matchCount, clear }` (from `useLayersContext().actions/meta`) |
| `LayersTree`/`LayerRow` | `useLayerRow` (exists) + `useLayersTree()` | rows, `treeProps` (role, keyboard), `rowProps(row)` |
| `CanvasWidthPresets` | `useWidthPresets()` | `{ presets, activeId, select }` |
| `CanvasDarkToggle` | `useDarkToggle()` | `{ pressed, toggle, buttonProps }` |
| `Zoom` | `useZoom()` | `{ levels, value, setZoom, isFit }` |
| `HistoryGroup` | `useHistory` (exists) | — |
| `InspectorVariants` | `useVariantBar()` | `{ variants, active, setActive }` |
| `ClassChips`/`ClassCombobox` | `useClassEditing` (exists) + `useClassSuggestions(query)` | list, add, remove, reorder, suggestions with `useDeferredValue` |
| `Inspector/controls/*` | `useStyleControl` (exists) | — |
| `InspectorAttributes` | `useAttributeFields(id)` | fields, `commit(name, value)` |
| `InspectorPosition` | `usePositionFields(id)` | `{ box, locked, commitPosition, commitSize, stacking: { index, last, move } , setLocked }` |
| `InspectorTransform` | `useTransformFields(id)` | `{ angle, autoHeight, aspectLocked, commitAngle, toggleAutoHeight, setAspectLocked }` |
| `Palette` | `usePaletteEntries()` + `usePaletteDraggable` (exists) | entries grouped by category |

Rules: hooks live next to the part (`Layers/useLayersSearch.ts`), are exported from `src/lib/index.ts`, and the core styled part becomes a thin consumer of its own hook. No behaviour changes in this step; existing tests keep passing untouched.

### 3.2 Skin parts

Mapping to shadcn components (per the `shadcn` skill selection table; `className` only for layout):

| Part | shadcn composition |
|---|---|
| `Layers.Header`/`Title`/`Count` | plain heading + `Badge variant="secondary"` |
| `Layers.Search` | `InputGroup` + `InputGroupInput` + `InputGroupAddon` (search icon, clear button) |
| `Layers.Tree`/`Row` | `ScrollArea`; rows are plain elements styled with `cn()` (not `Button`), chevron `Button variant="ghost" size="icon"`; `renderRow` from the core stays supported |
| `Layers.Empty` | `Empty` |
| `Canvas.Toolbar` | flex row with `gap-*`, `Separator orientation="vertical"` |
| `Canvas.WidthPresets`, `Canvas.Zoom` | `ToggleGroup type="single"` |
| `Canvas.DarkToggle` | `Toggle` with icon |
| `History` | `Button variant="ghost" size="icon"` + `Tooltip` (one `TooltipProvider` in the skin root) |
| `Inspector.Header` | heading + `Badge` for the tag |
| `Inspector.Variants` | `Tabs` + `TabsList` + `TabsTrigger` |
| `Inspector.Section`/`Category` | `Accordion` (collapsible categories) |
| `Inspector.ClassInput` | `Popover` + `Command` (`CommandInput`, `CommandGroup`, `CommandItem`) |
| `Inspector.ClassList` | `Badge` per class with a remove `Button` |
| `Inspector.Control` | `ToggleGroup` for enumerations, `Select` for scales, `Input` for arbitrary values |
| `Inspector.Attributes`, `Position`, `Transform` | `FieldGroup` + `Field` + `FieldLabel`, `InputGroup` with unit addons (`px`, `°`), `Checkbox` for locks, `ToggleGroup` for stacking order |
| `Inspector.Empty` | `Empty` |
| `Palette` | grid of `Button variant="outline"` with `data-icon`, `Tooltip` for the template description |
| `DefaultLayout` | `ResizablePanelGroup` with three `ResizablePanel`s |

Every skin part spreads the props object from its hook first and adds only `className` and shadcn-specific props after, so `data-*`/aria attributes and handlers cannot be overridden by accident.

### 3.3 Build

`vite.lib.config.ts`:

```ts
build: {
  lib: {
    entry: { index: 'src/lib/index.ts', shadcn: 'src/shadcn/index.ts' },
    formats: ['es'],
    cssFileName: 'style',
  },
  rollupOptions: {
    external: [
      'react', 'react-dom', 'react/jsx-runtime', 'react-dom/client',
      /^@base-ui\/react(\/|$)/, /^@radix-ui\//, 'lucide-react', 'class-variance-authority', 'clsx',
    ],
    output: { chunkFileNames: 'chunks/[name]-[hash].js' },
  },
}
```

- `tailwind-merge` is already a core dependency; the skin's `cn()` reuses it.
- `tsconfig.types.json`: `rootDir: ./src`, `include: ["src/lib", "src/shadcn"]`, output `dist/lib/**` and `dist/shadcn/**`; `exports` point `types` to `dist/lib/index.d.ts` and `dist/shadcn/index.d.ts`.
- `package.json`:

```json
"exports": {
  ".": { "types": "./dist/lib/index.d.ts", "import": "./dist/index.js" },
  "./shadcn": { "types": "./dist/shadcn/index.d.ts", "import": "./dist/shadcn.js" },
  "./style.css": "./dist/style.css"
},
"sideEffects": ["**/*.css"],
"peerDependencies": { "react": "^19", "react-dom": "^19", "@base-ui/react": "*", "lucide-react": "*", "class-variance-authority": "*", "clsx": "*" },
"peerDependenciesMeta": { "@base-ui/react": { "optional": true }, "lucide-react": { "optional": true }, "class-variance-authority": { "optional": true }, "clsx": { "optional": true } }
```

- The skin has no CSS file of its own; `dist/style.css` stays the core stylesheet.

### 3.4 Consumer setup (documented in the README)

```css
@import "tailwindcss";
@source "../node_modules/adt-html-editor/dist";   /* skin classes */
/* shadcn theme tokens from the consumer's own components.json / init */
```

```tsx
import 'adt-html-editor/style.css'
import { HtmlEditor } from 'adt-html-editor/shadcn'
```

The consumer's Tailwind preflight already reaches the canvas today (the canvas ships its own scoped preflight to counter it); the skin does not change that. Dark mode follows the consumer's shadcn setup (`.dark` on `html`); the canvas dark toggle keeps toggling `.adt-dark` on the page only.

### 3.5 Behaviour parity: shared conformance tests

One test module exports `describePartContract(name, render)` suites for each part family (layers search and tree keyboard, history buttons, class editing, position/transform fields, palette drag data). `src/lib/**/__tests__` runs them against the core parts; `src/shadcn/__tests__/conformance.test.tsx` runs the same suites against the skin parts. A part passes only if roles, names, `data-*` attributes read by the DnD layer, keyboard behaviour and store effects match.

### 3.6 Tree-shaking enforcement

- **Lint**: oxlint `no-restricted-imports` in `src/lib/**` for `@shadcn/*`, `../shadcn`, `@base-ui/react`, `@radix-ui/*`, `lucide-react`, `class-variance-authority`, `clsx`.
- **Build test** (`bundle.test.ts`, runs after `bun run build` in CI): parse `dist/index.js` and follow its static `import` graph across `dist/chunks/*`; assert no external matches the skin peer list and no chunk is shared with `dist/shadcn.js` that imports a skin peer. Also assert `dist/shadcn.js` does import the peers (so the test cannot pass vacuously).
- **Size budget**: `dist/index.js` + its chunks gzip size recorded in the test with a ±2% tolerance against the current build.

### 3.7 Performance rules for the skin

- No shadcn overlay (`Tooltip`, `Popover`) per tree row; one `TooltipProvider` at the skin root, tooltips only in toolbars and the palette (`rerender-memo`, keeps 1,000-row trees cheap).
- Rows use plain elements with `cn()`; `cva` variants are evaluated once per render, not per frame; drag frames never touch React (all imperative stores stay in the core).
- `Command` suggestions use the core's deferred query (`rerender-use-deferred-value`); the skin does not add state.
- No components defined inside components; `ui/*` imported directly (`bundle-barrel-imports`), no `ui/index.ts` barrel.
- Acceptance: `react-doctor --scope changed` at 100 for `src/shadcn/**`; `react-doctor scan` dragging in the 2,000-node fixture with the skin shows no frame > 16 ms attributed to the editor, same budget as the core.

## 4. Phases

### Phase S0 — Headless extraction in the core (1–2 days)
- [ ] Hooks from §3.1 added and exported; core styled parts rewritten on top of them; no visual or behavioural change.
- [ ] `describePartContract` suites written and passing against the core parts.
- **Done when**: `test`, `lint`, `typecheck`, react-doctor unchanged; every core part imports its hook; `src/lib/index.ts` exports the hooks.

### Phase S1 — Skin scaffold and build (1 day)
- [ ] `components.json` (base decided, style, icon library), `@shadcn/*` alias in TS and Vite, `cn()` and first `ui/*` via `bunx --bun shadcn@latest add`.
- [ ] Second entry, `exports`, optional peers, `tsconfig.types.json` layout, `bundle.test.ts`, oxlint restricted imports.
- [ ] Playground: Tailwind v4 + shadcn tokens in `src/playground/index.css` with `@source` limited to `src/shadcn`, layout option "shadcn" rendering the core `DefaultLayout` for now.
- **Done when**: `bun run build` emits `dist/index.js` and `dist/shadcn.js`; the bundle test proves `dist/index.js` has no skin peer; the playground renders with the new CSS without regressions in the core layouts.

### Phase S2 — Layers, History and Canvas toolbar (1–2 days)
- [ ] Skin `Layers.*` (search, tree, rows, empty), `History`, `Canvas.Toolbar`, `WidthPresets`, `DarkToggle`, `Zoom`.
- [ ] Conformance suites green against the skin parts.
- **Done when**: tree DnD, keyboard reordering and search behave identically to the core in the playground; react-doctor 100 on changed files.

### Phase S3 — Inspector (2 days)
- [ ] `Inspector.*`: header, variants (`Tabs`), sections (`Accordion`), class list (`Badge`), class input (`Popover` + `Command`), controls, attributes, `Position`, `Transform`.
- [ ] Conformance suites green.
- **Done when**: applying a class through the combobox shows in the canvas in < 50 ms as in the core; position/transform fields converge to the same `style` as handles and keyboard.

### Phase S4 — Palette and DefaultLayout (1 day)
- [ ] `Palette` with `Button` grid and drag data from `usePaletteDraggable`; `DefaultLayout` with `Resizable`.
- [ ] `src/shadcn/index.ts` namespace complete, canvas internals re-exported from the core.
- **Done when**: swapping the import path in the playground is the only change needed to get the skin; palette drops work into tree and canvas.

### Phase S5 — Hardening and docs (1 day)
- [ ] a11y audit of skin parts (focus, labels, 24 px targets, `prefers-reduced-motion`), `react-doctor scan` with the 2,000-node fixture.
- [ ] README: "shadcn skin" section (install peers, `@source`, tokens, `style.css` still required, `base` vs `radix`), limitations.
- [ ] Size budget recorded in `bundle.test.ts`.
- **Done when**: `test`, `lint`, `typecheck`, `build`, react-doctor clean; README updated; the bundle test is part of `bun run build` verification.

## 5. Risks and spikes

| Risk | Impact | Mitigation / spike |
|---|---|---|
| Rollup merges skin-only code into a chunk that `dist/index.js` also imports | S1 | Bundle test on the real graph; if it happens, `output.manualChunks` isolating `src/shadcn/**` and skin peers into `shadcn-*` chunks. |
| Consumer's Tailwind does not scan `dist` and skin classes are missing | S1 | `@source` line documented; playground reproduces the consumer setup; spike: `bun run build:playground` against `dist` instead of `src`. |
| Two primitive libraries in the consuming app (`base` here, `radix` there) | S1 | Decision point before S1 with the consuming app; `components.json` `base` is the only switch. |
| `tsconfig.types.json` `rootDir` change moves `dist/index.d.ts` | S1 | `exports.types` updated in the same commit; `attw`/`tsc --moduleResolution bundler` check in the bundle test. |
| Behaviour drift between skin and core | S2–S4 | Conformance suites are the contract; a skin part cannot ship without its suite. |
| Skin components heavier per row (cva, Slot, portals) | S2 | Rows are plain elements; tooltips only in toolbars; `react-doctor scan` on the 2,000-node fixture. |
| shadcn upstream changes to `ui/*` | Ongoing | Updates only through `shadcn add --dry-run/--diff`; local edits to `ui/*` avoided so overwrite stays safe. |
| Core CSS Modules and skin Tailwind both styling the same element | S2 | Skin parts never reuse core `.module.css`; core overlays that stay (selection, ghosts, guides, handles) are not chrome and keep their CSS. |

---

## 6. Out of scope

Precompiled skin theme, runtime theme switching, a `radix` and a `base` build side by side, restyling canvas content, npm publishing, other skins (MUI, Chakra) — though the headless hooks from S0 make them possible the same way.
